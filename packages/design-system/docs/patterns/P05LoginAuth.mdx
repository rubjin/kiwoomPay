# P05 Login → Auth

로그인(아이디 · 비밀번호) → 2차 인증(SMS) → 원래 화면으로 이동하는 흐름입니다.

## 1. 흐름

1. 아이디 · 비밀번호를 모두 입력해야 [로그인 인증] 활성 (Enter도 제출)
2. 1단계 확인 → 실패: 아래 **상태별 처리** 표, 입력 유지 / 성공: SMS 인증 Modal
3. SMS 인증: 남은 시간 3:00 카운트다운, 6자리를 입력해야 [완료] 활성, [재발송]은 시간 · 입력 초기화
4. 만료(0:00) · 불일치 · 발송 실패 · 재발송 제한: 입력 아래 빨간 문구(Alert 없음, 모달 유지)
5. 5회 실패 잠김 · 세션 만료: Alert 후 로그인 화면
6. 성공 → 토큰 저장 → 원래 가려던 화면(없으면 메인)

처리 · 안내는 P04 `useAction`(중복 실행 방지 · 결과 Alert)을 그대로 씁니다.

- 인증번호 아래 문구가 겹치면 재발송 안내 > 만료 > 발송 실패 · 불일치 순서로 하나만 보인다
- 세션 만료는 인증번호 시간(3분)과 다른 로그인 인증 세션 기준 — 인증번호 시간이 남아 있어도 서버가 세션 만료를 주면 Alert
- Alert 두 줄 문구는 줄바꿈 문자(`\n`)로 넣는다 (Modal 설명이 줄바꿈을 그대로 보여 줌)

## 3. 규칙

- 남은 시간 계산(카운트다운)은 화면이 한다 — `VerifyCodeField`는 `remaining`(초)만 받는다
- 표시 위치는 위 상태별 처리 표를 따른다. 입력 아래 문구는 높이 변화 없음. `useAction`의 `failure`가 null을 돌려주면 Alert 없이 끝
- 실패해도 입력은 지우지 않는다 (비밀번호 · 인증번호 다시 확인)
- 로고 · 그림 · Footer는 앱 자산을 넘긴다 (시스템별로 다를 수 있음)

## 확인 필요

- 제목 32 ExtraBold는 Figma 텍스트 스타일에 없음 → 컴포넌트 SCSS 값으로 둠
- (임의 작업) 입력 중 밑줄 색(Primary 500) · 오류 밑줄, 재발송 완료 안내 Alert(표에 없음), 예시 계정
- SMS 인증 Modal은 Figma 노드가 없어 PNG 측정값 + 사용자 확정(상자 ↔ 인증번호 12, 입력 ↔ 오류 문구 4)
- 내용 ↔ Footer 최소 간격(40), 가맹점관리자 반응형(모바일 시안 없음)
