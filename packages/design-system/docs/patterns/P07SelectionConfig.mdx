# P07 Selection & Configuration

사용자가 **목록에서 고르거나 설정을 바꾸고 저장**하는 팝업 패턴입니다 (Figma Pattern Library P07).
기준 화면: KWPC1301 LNB 즐겨찾기 편집(29348:37) · KWPC04010107 엑셀 다운로드 설정(29495:87846) · KWPC04010105 내 검색조건 관리(29503:90470). 모두 Modal lg 880, Footer 버튼 lg 48.

| 유형            | 부품                                                      | 예                 |
| --------------- | --------------------------------------------------------- | ------------------ |
| V01 메뉴 선택   | `FavoriteMenuPicker`                                      | 즐겨찾기 편집      |
| V02 선택 · 순서 | `TransferList` (전체 항목 ⇄ 선택 항목, 끌어서 순서)       | 엑셀 다운로드 설정 |
| V03 저장 조건   | `SavedConditionList` + `ConditionSummary` (`ConfigSplit`) | 내 검색조건 관리   |

설정 Modal 본문 조각: `ConfigField`(라벨 13 Bold + 내용, 라벨 ↔ 내용 30) · `ConfigHint` · `ConfigDivider`. 패널 제목(전체 항목 · 저장된 검색조건 · 선택한 검색조건 관리 등)은 다른 화면 영역 제목과 같은 `SectionHeading size="md" as="h3"`(16 Bold, 오른쪽 `actions`에 총 N 건 · [신규 등록]).
표시항목 설정처럼 칸을 한 화면에 늘어놓고 고르는 경우는 기존 `ColumnPicker`.

## 1. 흐름

1. 열 때 저장값을 **초안**으로 복사 (`useConfigDraft` → `begin()`)
2. Modal 안에서는 초안만 바꾼다 — 화면(LNB 등)은 저장 전까지 그대로
3. [저장]: 바뀐 것이 있을 때만 활성 → 저장(P04 `useAction`) → 저장값 반영 · 닫기 → 완료 Alert
4. [취소] · X · Esc: 바뀐 것이 있으면 "변경한 내용이 저장되지 않습니다. 닫을까요?" 확인

<Canvas of={Stories.FavoriteEdit} />

```tsx
const config = useConfigDraft(favoriteIds); // { draft, setDraft, dirty, begin, reset }
const save = useAction({
  run: () => api.saveFavorites(config.draft),
  onSuccess: () => {
    setFavoriteIds(config.draft);
    setOpen(false);
  },
  success: '즐겨찾기를 저장했습니다.',
});
const close = async () => {
  if (config.dirty && !(await dialog.confirm('변경한 내용이 저장되지 않습니다. 닫을까요?'))) return;
  setOpen(false);
};
```

## 2. V02 엑셀 다운로드 설정

- 다운로드 유형(Radio 가로) · 엑셀 템플릿(Select + [불러오기] [저장] [삭제]) · 전체 항목 ⇄ 선택 항목 · 안내 Infobox
- 왼쪽에서 체크 → [추가](선택 항목 끝에), 오른쪽에서 체크 → [제거]. 선택 항목 순서 = 엑셀 열 순서, 줄을 끌어서 바꾼다
- [엑셀 다운로드]: 선택 항목이 없으면 안내 후 중단 → 요청(P04 `useAction`) → 닫기 · 완료 안내

## 3. V03 내 검색조건 관리

- 왼쪽: 저장된 검색조건(검색 · 카드 · 10개씩 Pagination). 카드 상태 Badge — 적용 중(success) · 삭제 예정(error)
- 오른쪽: 선택한 조건의 이름 수정 · 저장된 조건 요약(`ConditionSummary`) · [현재 조건 덮어쓰기] · [삭제]/[삭제 취소] · [선택 조건 적용] · [신규 등록](현재 화면 조건으로)
- 모든 변경은 초안 — [저장] 때 삭제 예정은 지우고, 적용한 조건이 바뀌었으면 화면 검색 조건을 그 조건으로 바꾼다(조회는 사용자가 [조회])
- 요약 문구는 화면의 검색 조건 정의(`SearchFieldDef` + `summarizeSearch`)로 만든다 — 적용 조건 칩과 같은 정의

### 저장된 조건이 없을 때

- 맨 위 안내: "저장된 검색조건이 없습니다. 현재 화면의 검색조건을 새로 저장할 수 있습니다."
- 왼쪽: 검색창은 그대로, 남은 자리 가운데에 "저장된 검색조건이 없습니다."(14 SemiBold) + 설명(12 Regular) — `SavedConditionList`가 `items`가 비면 그린다(검색어가 있으면 "검색 결과가 없습니다.")
- 오른쪽: "신규 검색조건 등록" — 검색조건명 + 저장할 조건(현재 화면 조건 요약) + 안내. 삭제 · 적용 · Infobox 없음
- [저장]은 처음부터 활성, 이름이 비어 있으면 안내 후 중단

## 4. 규칙

- 선택 개수 제한은 부품이 막는다 (다 차면 나머지 비활성) — 저장할 때 다시 검사하지 않는다
- 저장 · 실패 안내는 P04 (Alert, 실패하면 Modal · 초안 유지)
- 기본값 복원이 필요한 설정은 `reset()`(저장값으로) 또는 화면이 기본값을 `setDraft`
