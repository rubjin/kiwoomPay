# P04 Action → Feedback

버튼 하나로 **처리(저장 · 변경 · 요청)** 를 실행하고 결과를 알려주는 흐름입니다 (Figma Pattern Library P04).
입력이 필요한 처리는 **sm(400) 입력 팝업**으로 받습니다. 예: 엑셀 다운로드 사유 입력, 사업자번호 변경.

## 1. 흐름

| 단계    | 내용                                                     | 화면                                      |
| ------- | -------------------------------------------------------- | ----------------------------------------- |
| Check   | 필수 · 형식 · 같은 값 확인. 문제가 있으면 Alert 후 중단  | 입력은 그대로, 팝업도 그대로              |
| Confirm | 되돌리기 어려운 처리는 무엇이 어떻게 바뀌는지 묻는다     | `dialog.confirm` (버튼 문구는 동작 이름)  |
| Process | 처리 중 실행 버튼 loading, 다시 눌러도 무시, 닫기 막음   | `loading`                                 |
| Result  | 성공: 팝업 닫기 · 값 반영 → 완료 Alert. 실패: 실패 Alert | 실패하면 **입력 유지** — 고쳐서 다시 시도 |

```tsx
const change = useAction({
  validate: () => (!BIZ_NO.test(next) ? '000-00-00000 형식으로 입력해주세요.' : null),
  confirm: () => `사업자번호를 ${current} → ${next}(으)로 변경할까요?`,
  confirmOptions: { confirmText: '변경' },
  run: () => api.changeBizNo(next, reason),
  onSuccess: () => {
    onChanged(next);
    onClose();
  }, // 닫기 · 재조회는 완료 안내보다 먼저
  success: '사업자번호가 변경되었습니다.',
  failure: '이미 등록된 사업자번호입니다. 번호를 확인해주세요.',
});

<Button size="lg" loading={change.loading} onClick={() => change.execute()}>
  확인
</Button>;
```

## 2. sm 입력 팝업

| 부품                         | 내용                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| `Modal` (기본 `size` sm 400) | 제목 + 닫기(X). 처리 중에는 닫기 · Esc 막음(`onClose` 생략)            |
| `Field` (라벨 왼쪽)          | 라벨 폭은 가장 긴 라벨에 맞춰 통일(`labelWidth`), 줄 간격 12           |
| 현재 값                      | 읽기 전용 입력(`readOnly`) — 바뀌기 전 값을 같은 줄 모양으로 보여 준다 |
| `Modal.Footer`               | [취소(Neutral Line)] [확인(Primary)], 버튼 lg, 가운데                  |

## 3. xl 입력 표 팝업

입력 칸이 표 모양으로 많으면 `size="xl"`(1280). 예: 카드번호별 매입사 결제한도 설정 — 업종 Button Tab(sm) + `FormTable`(카드사 × 일 결제횟수 · 1회 · 일 · 월 결제금액, 단위는 칸 오른쪽) + [취소][등록].

- 금액 · 횟수는 숫자만 받고 천 단위 쉼표로 보여 준다 (보관은 숫자만)
- Tab을 바꿔도 다른 Tab의 입력은 유지, [등록]은 모든 Tab을 한 번에 등록
- 흐름은 같다: 입력 확인 → Confirm → 등록 → 닫고 완료 안내

## 4. 규칙

- 결과 안내는 Alert (Toast 없음). 성공 안내는 팝업을 닫은 뒤, 실패 안내는 팝업 위에
- 처리 중에는 [확인] loading · [취소] 비활성 · 닫기(X) · Esc 막음
- 실패해도 입력값을 지우지 않는다
- Confirm 문구는 "무엇을 → 어떻게"를 쓴다 (예: 현재 번호 → 변경 번호)
