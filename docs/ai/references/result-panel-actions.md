# 조회 결과 Action 배치 기준

> 디자인 없이 기획서(화면설계서)만으로 조회 화면(P01)을 만들 때 따르는 기준. 사용자 제공 참조 이미지(2026-11-17).

![조회 결과 Action 배치](./result-panel-actions.png)

## 배치

```
조회 결과  [Grid 설정 Action] [데이터 내보내기 Action]            [데이터 처리 Action] [상태 변경 Action] [+ 데이터 등록 Action]
└ 왼쪽: Grid 기능 Action — 표시 구성 · 데이터 내보내기           └ 오른쪽: Data 업무 Action — 선택 데이터 처리 · 상태 변경 · 등록 (화면별 정의)
```

| 자리 | `ResultPanel` prop | 들어가는 버튼 (기획서 표현 예) | 버튼 모양 |
| --- | --- | --- | --- |
| 제목 옆(왼쪽) | `titleActions` | Grid 기능: 표시항목설정 · 열 설정 · 엑셀 다운로드 · 내보내기 | `size="sm" variant="neutral" appearance="line"` |
| 오른쪽 ① | `actions` | 데이터 처리: 선택 대상 처리 · 재산출 · 일괄 변경 · 보류 등 | `size="sm" variant="neutral" appearance="line"` |
| 오른쪽 ② | `actions` | 상태 변경: 확정 · 승인 · 상태 바꾸기 등 화면의 핵심 처리 | `size="sm" variant="dark"` |
| 오른쪽 ③ (맨 끝) | `actions` | 데이터 등록: 신규 등록 · 추가 | `size="sm"`(Primary) + `leadingIcon={<Icon name="plus" size={20} />}` |

## 규칙

- 제목은 `ResultPanel title`(기본 "조회 결과"). 버튼 사이 간격은 컴포넌트가 정한다(8) — 인라인 간격 금지
- 왼쪽(Grid 기능)은 화면 데이터와 상관없는 Grid 도구만. 업무 처리 버튼을 왼쪽에 두지 않는다
- 오른쪽은 처리(Line) → 상태 변경(Dark) → 등록(Primary + 아이콘) 순서. **Primary는 등록 하나, 맨 오른쪽**. 없는 종류는 빼고 순서만 지킨다
- 같은 종류가 여러 개면 같은 모양으로 나란히(예: 처리 Line 3개)
- 조회 전 · 결과 없음이면 Grid 기능 · 처리 · 상태 변경은 비활성. 선택이 필요한 처리는 누를 때 선택 확인 → Alert 또는 처리 팝업(P04 `useAction`)
- 앱 화면에서는 버튼 처리 중 표시를 하지 않는다(확정 결정 "버튼 처리 중 표시")
- 기획서에 버튼 이름만 있고 종류가 불분명하면 위 표로 분류하고, 애매한 것은 "(임의 작업)"으로 표시 후 확인 요청

## 적용 예

- KWPC04010100 통합 거래내역: 왼쪽 [표시항목설정] [엑셀 다운로드]
- KWPC06010201 가맹점 정산 실행/처리: 왼쪽 Grid 기능, 오른쪽 처리 Line(지급예정일 일괄 변경 · 지급보류 · 보류해제 · 재산출) → [지급확정] Dark → [+ 조정 원장 등록] Primary
  - 참고: [+ 상계 원장 등록]은 Dark + 아이콘으로 되어 있음 — 이 기준대로면 등록은 Primary 하나라 확인 필요
